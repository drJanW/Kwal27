Q1  Do NORMALISATION.txt + calibration.txt supersede plan_b10?
    ANSWERED 2026-03-02: PNF/CNF are fresh untested ideas. If approved
    after review, the normalisation concept overrules plan_b10. Both
    docs remain active — they serve different purposes (theory vs impl).

Q2  Do PNF and CNF need to exist as separate pre-steps?
    ANSWERED 2026-03-02: Same as Q1 — PNF/CNF concept needs approval
    first. If approved, they become mandatory prerequisites for lux cal.

Q3  HOUT has no lux sensor — how to develop/test?
    ANSWERED 2026-03-02: Development split across devices:
    - HOUT (189): normalisation code, web GUI, implementation logic
    - MARMER (188): lux calibration (real sensor, user deploys)
    - HOUT implementation: needs strategy for missing lux sensor
      (dummy lux? simulated readings? skip lux path?)

Q4  Should a*(lux+b)^c replace the current shift pipeline?
    ANSWERED 2026-03-02: No. Keep Stevens' power law. See E1 resolution.
    The a*(lux+b)^c model in NORMALISATION.txt will be updated to match.

Q5  What happens with the clamping problem (E5)?
    ANSWERED 2026-03-02: Solved by calibration-mode. Web GUI gets a
    calibration panel (toggle on/off). While active, calcShiftedHi()
    stores the pre-clamp float in a side variable. Thumbs-up logs
    (lux, unclampedBrightness). No runtime overhead when inactive.
    Calibration UI is needed anyway for the thumbs-up button.

Q7  Is 500 seeds excessive?
    ANSWERED 2026-03-02: The 500-seed FIFO belongs to plan_b10's
    pre-PNF/CNF approach. With SNB, calibration data model will
    change. Revisit buffer size when designing the SNB data store.

Q8  Per-pattern/color corrections: 99 slots enough?
    ANSWERED 2026-03-02: 99 is arbitrary, 43 (30+42 rounded) also.
    The real question is not the number but the overflow strategy:
    FIFO? LRU? Reject? This merges with Q6. Decide buffer policy
    when designing the SNB calibration data store.

E1  Model mismatch                              RESOLVED 2026-03-02
    NORMALISATION.txt + calibration.txt used a*(lux+b)^c.
    plan_b10_lux_calibration.md uses the current shift pipeline
    (Stevens' power law). Decision: keep Stevens' power law (Model B).
    Rationale: already implemented, human-readable params, natural
    grid search, low-lux emphasis via gamma<1. Approach named "SNB"
    (Stevens Normalized Brightness). See plan_snb.md.

E2  MAX_AUDIO_VOLUME in brightness formula       FIXED 2026-03-02
    Was: baseGain = MAX_AUDIO_VOLUME × fContext × fWebsite × fOptional
    Fixed to: baseGain = brightnessHi × calendarShift × webMultiplier
    in both NORMALISATION.txt and calibration.txt.

E3  luxMeasurementDelayMs mismatch              FIXED 2026-03-02
    Was dead config — declared in Globals.h, parsed from CSV, but
    never used. cb_fadeBrightnessOut() called cb_measureLux() directly.
    Fix: replaced direct call with timers.create(luxMeasurementDelayMs,
    1, cb_measureLux) to give VEML7700 settling time after LEDs go dark.
    800 vs 200 default mismatch is irrelevant — CSV wins at runtime.

Q6  Dedup or FIFO — pick one?
    DEFERRED 2026-03-02: No implementation exists yet. Decide buffer
    policy (dedup vs FIFO, overflow strategy) when designing the
    SNB calibration data store in Part 2.

E4  brightnessLo mismatch                       NOT AN ERROR 2026-03-02
    Globals.h default = 70, globals.csv sets 16. By design — CSV
    overrides are the intended runtime values, Globals.h = fallback.

E5  Clamping breaks luxBrightness normalization  RESOLVED 2026-03-02
    Solved by calibration-mode (see Q5). During calibration, the
    pre-clamp float is stored in a side variable. No runtime impact.

E6  SEED marker vs uint8_t                      DEFERRED 2026-03-02
    No calibration data store exists yet. Design note for Part 2:
    use 0 as sentinel (IDs start at 1).

E7  Deduplication vs FIFO conflict               DEFERRED 2026-03-02
    No FIFO exists yet. Covered by Q6 — decide buffer policy
    when designing the SNB calibration data store in Part 2.

E9  maxBrightness vs brightnessHi ambiguity      NOT AN ERROR 2026-03-02
    Different concepts: maxBrightness = hardware ceiling (FastLED),
    brightnessHi = SNB pipeline ceiling (policy). Changed maxBrightness
    from 242 to 248 to make the distinction visible.

E8  IDs are String, not uint8_t                  DEFERRED 2026-03-02
    Not a current bug — all callers use String correctly today.
    Design note for Part 2/3: when building PNF/CNF lookup tables,
    need .toInt() + bounds check to convert to numeric index.

E10 PNF/CNF ordering requirement                 RESOLVED 2026-03-02
    SNB plan overrules plan_b10: Part 1 (freeze PNF/CNF) must
    complete before Part 2 (lux calibration). Documented in
    plan_snb.md ordering rule.
